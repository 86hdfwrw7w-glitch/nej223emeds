## Was diese Skill tut

Fährt einen vollständigen Review einer **PDF** (Abschlussarbeit, Paper, Bericht) über ein Multi-Agenten-Team: Lektorat pro Kapitel, Quellenprüfung (inhaltlicher Abgleich gegen Original-PDFs + Zitierformat + Web-Verifikation), Zahlen-Abgleich Text↔Output-Tabellen, Notebook-/Code-Logik und Querschnitt (Querverweise, roter Faden, Terminologie). Ergebnis: ein detaillierter Markdown-Report **pro Kapitel + Befund-Typ**, abgelegt neben der PDF.

## Harte Regeln (nicht verhandelbar)

- **Das Quelldokument wird NIE verändert.** Insbesondere wird eine zugehörige `.docx` **niemals** angefasst (nicht öffnen-zum-Schreiben, nicht konvertieren-überschreiben). Review läuft ausschließlich auf der PDF.
- **Deterministisches Rendering**: Den finalen Report rendert ein **Python-Skript** aus den zurückgegebenen Befunddaten — **keine Render-Agenten** (die fallen bei großen Läufen an API-Fehlern aus). Der Workflow gibt die vollen Befunddaten zurück, nicht gerenderte Teildateien.
- **Kostengate vor dem Lauf**: Erst Material-Zuordnung bestätigen lassen und die Konfig-Fragen stellen, dann den (teuren, ~50–90 Agenten) Workflow starten.
- PDFs mit > 10 Seiten immer mit `pages`-Parameter lesen (gilt für die Quellen-Agenten beim Lesen der Original-Paper).
- Sprache des Reports = Sprache des Dokuments (Default Deutsch, Du-Form gemäß Nutzerpräferenz).

## Voraussetzungen

Python 3 mit **PyMuPDF** (`import fitz`). Prüfen mit:
`python -c "import fitz; print(fitz.__doc__[:20])"`. Fehlt es: dem Nutzer melden (`pip install pymupdf`), nicht ungefragt installieren. Pandas wird **nicht** benötigt (CSV ohne pandas lesen).

Alle technischen Details, Skript-Vorlagen und die Workflow-Vorlage stehen in **[reference.md](reference.md)** — beim Bauen des Workflows von dort kopieren und anpassen.

## Ablauf

### Schritt 0 — PDF bestimmen
PDF-Pfad aus `$ARGUMENTS` nehmen. Fehlt er, per AskUserQuestion erfragen oder im aktuellen Ordner nach der einzigen/größten PDF suchen und bestätigen lassen. Scratchpad-Arbeitsordner anlegen (`.../scratchpad/dokument-review/`).

### Schritt 1 — PDF extrahieren & Struktur erkennen
1. `config.json` im Scratch schreiben (`pdf_path`, `out`). `extract.py` (siehe reference.md) laufen lassen → `thesis_text.txt` (mit `===== PAGE N =====`-Markern), `toc.json`, Seitenanzahl, Per-Seite-Erstzeilen-Dump. **`PYTHONIOENCODING=utf-8`** setzen (Windows-Konsole).
2. Aus dem Inhaltsverzeichnis + dem Erstzeilen-Dump die **physischen** Seitengrenzen je Kapitel bestimmen. Front-Matter ist meist römisch nummeriert → der Offset (physische Seite = Body-Seite + k) muss über eine bekannte Überschrift verifiziert werden (eine TOC-Body-Seite gegen ihre physische Fundstelle abgleichen).
3. Die ermittelte **Seiten→Kapitel-Karte als Tabelle zeigen** und vom Nutzer bestätigen lassen.

### Schritt 2 — Material auto-erkennen
1. Umgebung der PDF (gleicher Ordner + Unterordner) scannen: **Paper** (`*.pdf` außer dem Dokument), **Notebooks** (`*.ipynb`), **Output-Tabellen** (`*.csv`).
2. `config.json` um `sections` (Name→[Start,End] physisch), `biblio_pages`, `body_pages`, `papers_dir` ergänzen; `prep.py` laufen lassen → Abschnittsdateien (`sections/*.txt`), `bibliography.txt`, `citations_*.txt`, `papers_inventory.txt`.
3. **Zitat→Paper-Mapping** bauen (Bibliographie-Einträge auf vorhandene lokale PDFs matchen; je Quelle einen `grepKey` = Nachname + Jahr). Substanzquellen (paraphrasierte Studien) von Methoden-Klassikern unterscheiden.
4. **Mapping anzeigen** (welche Quellen lokal abgleichbar sind, welche nur Web; Notebook-/Tabellen-Liste) und bestätigen lassen.

### Schritt 3 — Konfiguration (AskUserQuestion, klickbar)
Drei Fragen: (a) **Quellen-Tiefe** (Inhalt+Format+PDF / +Web / nur formal), (b) **Zahlen+Notebook-Logik** (ja/nein — nur falls Material vorhanden), (c) **Report-Format** (pro Kapitel+Typ / priorisierte Liste / Checkliste). Defaults: alles an, pro Kapitel+Typ.

### Schritt 4 — Workflow starten
Die Workflow-Vorlage aus reference.md übernehmen und füllen: `SCRATCH`, `CHAPTERS` (Abschnittsdatei + physische Seitenrange je Kapitel), `PAPER_MAP` (relPath, cite, grepKey, kind s/m), `NOTEBOOKS`, `TABLES`, `bucketForPage`-Grenzen. Phasen: Kapitel-Lektorat · Quellen (Bibliographie-Konsistenz + 1 Agent je lokaler Quelle + Web-Batches) · Zahlen + Notebook-Logik (+ Synthese) · Querschnitt · Aggregation. **Rückgabe = `{counts, byBucket, byKind, ORDER, flat, notes}`** (volle Daten, kein Agent-Render). Im Hintergrund laufen lassen.

### Schritt 5 — Report rendern (deterministisch)
Nach Abschluss: Die Workflow-Output-Datei (`.../tasks/<id>.output`) ist ein Wrapper `{summary, agentCount, logs, result}` — die Befunde liegen unter **`result`**. `config.json` um `task_output` + `dest` ergänzen; `render.py` (reference.md) laufen lassen → Report-Markdown. Falls einzelne Analyse-Agenten ausfielen: Workflow per `resumeFromRunId` neu abrufen (gecachte Ergebnisse kommen sofort).

### Schritt 6 — Gesamteinschätzung & Ausgabe
Oben in den Report eine handgeschriebene **Gesamteinschätzung** einfügen (aus `counts` + kritischen/wichtigen Befunden + Notebook-`notes`): Gesamturteil, Top-Prioritäten, ob der empirische Kern reproduzierbar ist. Report **neben die PDF** schreiben (`Review-Report_<Dokumentstamm>_<YYYY-MM-DD>.md`), dem Nutzer per `SendUserFile` schicken und ein knappes Fazit geben.

## Report-Aufbau

1. Titel + Metadaten (Basis-PDF, Datum, „Word unverändert“) + Methode.
2. **Gesamteinschätzung** (Prosa, handgeschrieben).
3. **Befundübersicht**: Tabelle je Kapitel + Tabelle je Befund-Typ + Gesamtzählung nach Schweregrad.
4. **🔴 Kritische Befunde zuerst** (Liste).
5. **Detail pro Kapitel → pro Befund-Typ**, je Gruppe sortiert kritisch → wichtig → kosmetisch; je Befund: `[Schweregrad · S.X] Problem — Zitat „…“ → Vorschlag (Konfidenz, ggf. Quelle)`.

## Notizen & Edge Cases

- **Seiten-Offset** ist die häufigste Fehlerquelle — immer gegen eine echte Überschrift verifizieren, nicht raten.
- **Keine eingebettete TOC** (`toc.json` leer) ist normal → Struktur aus dem Text ableiten.
- Quellen-Agenten **grep**en `thesis_text.txt` nach dem Nachnamen, um zitierende Stellen + Seite zu finden; bei mehreren gleichnamigen Autoren nach Jahr disambiguieren.
- **Skalierung**: 1 Agent je lokal verfügbarer zitierter Quelle (gründlichste Variante). Bei sehr vielen Quellen läuft das über mehrere Wellen (Concurrency-Cap) — das ist ok.
- Notebooks/Tabellen fehlen → die entsprechenden Tracks einfach weglassen (Schritt 3 erkennt das).
- Befunde nach **Kapitel der Fundstelle** buckets (über die Seitenzahl); reine Format-/Web-Quellenfehler ohne Seitenbezug landen im Kapitel „Literaturverzeichnis & Quellen“, Notebook-Befunde im Kapitel „Notebooks & Reproduzierbarkeit“.
- Nichts committen/installieren/löschen ohne explizites OK.
